## 1. 工作区与导航

界面采用两栏布局：左侧是文件夹树或聚合列表，右侧是编辑器。最近 / 全部笔记 / 收藏 / 标签 / 待办收在列表头的视图菜单里，菜单中还有「收起全部文件夹」和「刷新」。

- **目录树**：目录对应磁盘上的真实子文件夹。默认单行标题，单击打开；文件夹可展开、收起，当前笔记有底色和左侧强调线。支持方向键、Home / End、Enter 打开。
- **筛选状态保持**：从最近、收藏、标签或搜索结果打开笔记时，保留当前筛选；从待办跳转时保留待办页与关键词。从会话引用或关联笔记跳回时，打开「全部笔记」并定位目标。
- **收藏与置顶**：编辑器右上角的星标控制收藏，图钉控制置顶，两者独立保存。旧笔记的 `pinned` 仍只表示置顶，不会自动变成收藏。「最近」按更新时间取最近 15 篇，不受置顶优先级影响。
- **列表展示**：目录树与摘要列表可以切换；排序支持标题与更新时间。阅读模式、展开状态、排序和列表形态保存在本机。
- **右侧栏的工作区笔记**：右侧栏的「工作区笔记」页按当前会话所属的工作区收一份紧凑列表。库在工作区目录内时显示整库；工作区在库内时显示对应的相对文件夹；两者无关时按工作区目录名匹配库中的同名文件夹。点开一篇即可阅读，也能跳回完整面板编辑；列表头的「工作区 / 全部笔记」可切换范围。找不到对应文件夹时显示空状态，可查看全部笔记或直接新建；搜索、刷新、新建和字号跟随完整面板。
- **窄窗口**：窗口 ≤ 640px 时列表与编辑器纵向堆叠，分栏编辑也会改为上下排列。

## 2. 编辑、预览与搜索

- **三种模式**：编辑 / 分栏 / 预览。默认打开渲染后的正文，可随时切换。
- **实时预览**：分栏模式下源文与预览同步更新。中间分隔条可以拖动，也支持方向键微调，双击恢复 50/50；比例保存在本机。
- **工具栏**：加粗、斜体、行内代码、标题级别、列表、待办、引用、代码块、链接、表格。标题与「更多」使用下拉菜单，不打断输入焦点。
- **自动保存**：输入后 650ms 防抖保存，状态栏显示「已保存 hh:mm」。⌘S 可立即保存。
- **Markdown 支持**：标题、段落、有序 / 无序列表、任务列表、引用、行内代码与代码块、链接、分割线、管道表格。预览中的表格可横向滚动，表头保持可见。
- **全文搜索**：⌘K 聚焦搜索框，按标题 + 正文即时过滤；命中的文字在列表和待办中高亮。
- **标签**：每篇笔记可加多个标签；标签页按出现次数聚合，点标签即筛选。
- **路径**：编辑器顶部的面包屑显示当前笔记所属文件夹。
- **保存顺序**：保存期间继续输入的内容会在下一次保存中提交。切换笔记或勾选待办前，会先等待当前保存完成。
- **冲突处理**：外部刷新只同步没有本地修改的正文。保存冲突会保留本地文字并显示错误；只有明确选择「重新载入」才会放弃未保存内容。
- **收藏 / 置顶与正文分离**：星标和置顶的变化不会改变正文修订号，因此不会和编辑产生无关冲突。

## 3. 待办中心

- 聚合整个库里的 `- [ ]`，按任务文字、来源笔记标题或标签搜索；搜索同时覆盖未完成和已完成项。
- 顶部显示完成进度与百分比，可用「全部 / 未完成 / 已完成」筛选。
- 勾选后回写原 Markdown 文件，并同步当前打开的源文与预览；当前打开笔记里的复选框也会反写。
- 每行带内容修订校验：笔记在别处发生变化导致旧行失效时，列表会刷新并提示重新勾选。
- 已完成项列在下方；来源笔记标题可点击跳转。
- 没有待办或筛选结果为空时，会显示对应的空状态，而不是一片空白。

## 4. 对话与笔记

### 会话沉淀

任意会话标题栏右侧的「存为笔记」把当前会话的用户 / 助手对话整理成一篇带日期的笔记，自动打上「会话沉淀」标签。

### 笔记加入对话

笔记顶部的「加入对话」可以：

- 发送整篇笔记快照；
- 或只加入在编辑区 / 预览区选中的片段；
- 选择现有对话，或沿用 Harness 工作区流程打开新对话。

内容通过 Harness 原生输入接口插入草稿，保留已有文字、引用和撤销历史，**不会自动发送**。单次最多加入 12,000 个 Unicode 字符，截断会明确提示。

### 回答保存到笔记

回答操作栏中的「保存回答到笔记」可以新建笔记或追加到已有笔记，保存前预览原文。

- 只读取持久助手消息中的文字，不保存思考或工具调用。
- 同一来源重复保存会去重。
- 追加前校验目标笔记的修订号；目标已变化时要求重新确认。

### 来源双向跳转

- 笔记的「来源与关联」可返回来源会话，并展示对应回答原文、轮次和时间。
- 会话标题栏的「关联笔记」可反向打开笔记。
- 发送后的笔记引用也可点击打开。

来源写入 Markdown frontmatter 的 `dsh_sources`，所以改标题或重启后仍然保留。「加入过此会话草稿」只表示草稿关联，不代表已经发送或执行。

会话来源通过 Harness 的 `sessionQuery.readSession / readSurface` 读取，因此已持久化的冷会话也能工作；回答保存需要启用该服务。整个会话导出在服务缺失时仍读取实时会话。

### 两个已知边界

- 当前 Harness 没有公开的「滚动到某条聊天消息」接口。跳回来源回答会打开原会话并展示回答原文，但不会自动滚动聊天时间线，也不会用 DOM 查询假装定位。
- 原始会话被删除、笔记文件被移动或库目录改变时，跳转可能失败，界面会明确报错。旧笔记没有来源身份时，不会根据标题猜测关联。

## 5. Agent 读写

注册了四个工具：

| 工具 | 作用 |
| --- | --- |
| `note_list` | 列出笔记与文件夹 |
| `note_search` | 按标题、正文、标签搜索 |
| `note_read` | 读取一篇笔记 |
| `note_write` | 新建或更新笔记 |

于是「帮我找一下双十一活动的接口文档」这类话可以直接在笔记库里命中，而不需要先把内容贴进对话。

## 6. 数据与存储

### 位置

- 默认：`rootDir` 留空时是 `<Harness 默认工作目录>/notes`。
- 环境变量：`DSH_NOTES_DIR`。
- 设置页：`设置 → 笔记 → 笔记库目录`（推荐）。保存后插件自动重载并立即生效，写入 profile 覆盖层。
- 配置文件：修改 `cordis.patch.yml` 的 `config.rootDir` 后重装 bundle。

### 文件格式

一篇笔记就是一个普通 Markdown 文件：

```markdown
---
title: 双十一广告转盘活动 · 接口评审
tags: [活动, 接口]
created: 2026-11-09T03:34:19.511Z
updated: 2026-11-09T03:35:23.241Z
pinned: false
starred: false
---

## 背景
...
```

可用任何编辑器、git 或 Obsidian 直接打开。

- **笔记 id**：相对库目录的路径去掉 `.md`，例如 `工作/2026/接口评审`。原有根目录笔记 id 保持不变；改标题不会重命名文件。
- **目录**：目录树对应真实子文件夹；插件不会按标题或标签自动移动笔记；不读取符号链接。
- **重名**：同一目录下创建重名笔记时会生成不冲突的文件名。

### 界面偏好

字号、目录树 / 摘要、排序、默认阅读模式和分栏比例保存在本机 `localStorage`，键前缀 `dsh-note:`。它们不随库同步，也不会跟随到其他设备。

### `dsh_sources`

`dsh_sources` 是插件维护的 JSON 数组：

- 回答来源：`sessionId` / `messageId` / `seq` / `turn` / `time`；
- 笔记引用关联：会话 id、笔记内容修订摘要、整篇或片段范围、`draft` 状态。

正文编辑会保留这些来源。星标 / 置顶操作不会改变正文修订号。

## 7. 设置

`设置 → 笔记` 提供：

- 当前库路径与统计（笔记 / 文件夹 / 标签 / 未完成待办）；
- 笔记库目录输入框，保存后插件自动重载；
- 字号：小 / 标准 / 大 / 特大，立即生效，只影响本机；
- 「打开笔记面板」入口；
- 快捷键说明：⌘K 搜索，⌘S 立即保存；
- 数据格式提示。

## 8. 实现与接口

### 文件

```
index.js          Host 半：vault 读写、/api/dsh-note 路由、note_* 工具
client.js         Client 半：两栏界面、右侧工作区页、Markdown 渲染、会话联动
package.json      bundle 清单（dsh.bundle.patch + dsh.client）
cordis.patch.yml  插入 dsh-note 插件行并配置 rootDir
locale/{zh,en}.json  插件管理器标题与描述
icon.svg          面板图标
screenshots.json  插件市场截图清单
assets/           图标、截图与演示动图
docs/             长文文档
*.test.js         22 个测试
```

### HTTP API

`POST /api/dsh-note`：

- 基础 action：`list` / `get` / `create` / `createFolder` / `save` / `delete` / `search` / `todo` / `deposit`
- 联动 action：`answer` / `saveAnswer` / `links` / `prepareReference` / `recordReference`
- 设置 action：`set-root`，通过 `configEditor` 写回 `rootDir`；先回包，再让插件重载。

路由仅接受本机回环请求并做同源校验。`list` 返回 `folders` 以及每篇笔记的 `sources` / `revision`；`saveAnswer` 追加时要求匹配的 `expectedRevision`。`create` 可传相对库目录的 `folder`；`createFolder` 接收 `name` 和可选 `parent`。

### Host 依赖

`tools`、`webServer`。没有第三方 npm 运行时依赖，也没有构建步骤。

### Client

- 复用 `sessions` / `uiSession` 管理会话生命周期与输入标准属性；
- 复用 `uiWorkspace` 导航和工作区新会话准备流程；
- 通过 `inputActions.captureInsertion / insertText / persistDraft` 插入草稿；
- 通过 `uiConversation.userText` 渲染笔记引用；
- 通过 `sidebarRightTabs` 注册右侧栏「工作区笔记」页，正文挂到 `sidebar.right.pane.tab` 的插件 id 下；工作区从 `sessions` / `workspaces` 解析；
- 入口注册在回答操作、会话标题操作和 `shell.overlay` 插槽；卸载插件会释放这些注册。

### 主题与样式

界面是一套「纸与墨」的独立视觉：暖纸色背景、墨色文字、青绿强调与朱红印章，同时完全基于 Harness 的主题 token，用 `color-mix()` 随明暗主题自动变化。

- 字体：正文跟随宿主；标题使用宋体 / 衬线字体，代码使用宿主等宽字体。
- 尺寸：字号偏好通过 `--dn-fs` 驱动整套字号阶梯，最小字号有下限。
- 动效：`prefers-reduced-motion` 下关闭过渡；焦点环区分文本输入与按钮。
- 响应式：编辑器区域使用容器查询；列表与编辑器的堆叠使用视口媒体查询。

## 9. 本地验证

在仓库根运行：

```sh
npm run check   # 语法检查
npm test        # 22 个测试
```

测试覆盖目录递归、嵌套笔记读写 / 搜索 / 待办、根目录兼容、重名处理、路径边界、冷会话回答读取、重复保存、追加冲突、来源保留、引用快照、原生草稿插入调用、独立收藏 / 置顶、待办搜索，以及编辑器刷新 / 顺序保存。测试在临时目录执行，不会修改真实笔记库。

GitHub Actions 在 Node 22 / 24 上执行同样的 `npm run check` 与 `npm test`。

## 10. 已知边界与路线图

还没做：

- `[[wiki links]]` 与知识库；
- 文件夹移动 / 重命名；
- 网页剪藏；
- AI 摘要与续写；
- 有道云笔记同步（本机已有 `youdaonote` CLI 可复用）；
- 每日日记模板。

已知限制：

- 来源回答跳转不能滚动到具体聊天消息（Harness 没有公开接口）；
- 会话、笔记或库目录被移走后，旧来源链接可能失效；
- 界面偏好只在本机，不随库同步。
